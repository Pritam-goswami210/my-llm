# Stage 8 Training Pipeline Report
============================================================

## 1. Overview

Stage 8 Phase D/E implements a multi-dataset weighted training pipeline
for TinyLM. The pipeline reads the corpus manifest, loads available
datasets, and samples training batches from each corpus according to
its configured weight.

## 2. Architecture

### Weighted Corpus Sampler (`WeightedCorpusSampler`)

Each corpus is encoded as a separate 1-D tensor of token IDs. At each
training step:

1. A corpus is selected by weighted random choice (cumulative weight
   distribution).
2. A random batch of windows is drawn from that corpus only.
3. No sequences cross scene/document boundaries.

This ensures that each corpus contributes to training in proportion to
its configured weight, and that no context leaks between documents or
scenes.

### Checkpointing

Checkpoints are saved under `checkpoints/stage8/` (never overwriting
the original `checkpoints/`). Each checkpoint includes:

- Model configuration (vocab_size, block_size, n_layer, n_head, n_embd, dropout)
- Tokenizer metadata (characters, special_tokens)
- Full corpus manifest
- Per-corpus info (chars, train_chars, val_chars, weight, file)
- Model state dict
- Optimizer state dict (AdamW moments)
- Training step, tokens seen, elapsed time, learning rate, random seed

### Resume Support

Training can be resumed from any Stage 8 checkpoint. The resume path
validates the checkpoint format and restores model weights, optimizer
state, step number, and learning rate.

## 3. Supported Corpora

The pipeline reads `data/manifests/corpus_manifest.json` which defines
5 corpora:

| ID | Name | Weight | Status |
|----|------|--------|--------|
| corpus-a-original | Original language material | 25% | Available (data/tiny_corpus.txt) |
| corpus-b-shakespeare | Shakespearean literary material | 25% | Available (data/processed/hamlet_clean.txt) |
| corpus-c-modern | Modern English material | 20% | Placeholder (no file) |
| corpus-d-conversation | Original conversational examples | 15% | Placeholder (no file) |
| corpus-e-teacher | Optional teacher-generated examples | 15% | Placeholder (no file) |

Only available corpora are used in training. Missing datasets are
reported but not fabricated.

## 4. Splitting Strategy

### Hamlet (corpus-b-shakespeare)

Split at SCENE boundaries using `data/processed/hamlet_scenes.jsonl`.
Whole scenes are assigned to train or validation. No scene appears in
both splits.

Result (seed 1337, val_frac 0.1):
- Train: 142,870 chars (17 scenes)
- Validation: 17,552 chars (3 scenes)

### Stage 5 Original (corpus-a-original)

Split at DOCUMENT boundaries using `data/stage5/sources/`.
Whole documents are assigned to train or validation. No document
appears in both splits.

Result (seed 1337, val_frac 0.1):
- Train: 11,669 chars (18 documents)
- Validation: 1,534 chars (2 documents)

## 5. Weight Enforcement

Hamlet's weight is enforced at its configured maximum (25%). The
sampler normalizes weights across available corpora, so if only 2
corpora are available (original + Shakespeare), each gets 50% of
training steps. When all 5 corpora are available, each corpus gets
its configured weight.

## 6. Training Loop

- Optimizer: AdamW
- Gradient clipping: configurable (default 1.0)
- Learning rate: configurable (default 1e-3)
- Batch size: configurable (default 8)
- Block size: configurable (default 128)
- Evaluation interval: configurable (default 8 steps)
- Save interval: configurable (default 16 steps)
- History CSV: `runs/stage8/train_history.csv`
- Columns: step, corpus, split, loss, elapsed_s, tokens_seen

## 7. CPU-Only Execution

All training runs on CPU. No CUDA or GPU assumptions are made. The
model (~822K parameters) is small enough to train on an
i5-4570T with 16 GB RAM.

## 8. Smoke Test Results

A 5-step smoke test was completed successfully:

- Loss decreased from 4.40 to 3.70 over 5 steps
- Per-corpus validation loss reported for each corpus
- Checkpoint saved and resumable
- Generation sample produced (expected gibberish for 5 steps)

## 9. Usage

```powershell
# Smoke test (5 steps, writes to checkpoints/stage8/)
python src\stage8\weighted_train.py --steps 5 --batch-size 4 --block-size 64

# Longer experiment (requires explicit approval)
python src\stage8\weighted_train.py --steps 100 --batch-size 8 --block-size 128

# Resume from checkpoint
python src\stage8\weighted_train.py --resume checkpoints\stage8\model.pt --steps 50
```

## 10. Limitations

- Only 2 of 5 corpora are available (C, D, E are placeholders)
- Weighted sampling normalizes across available corpora only
- 5-step smoke test is insufficient for meaningful language learning
- Natural language communication requires much more data and training
  steps (Phase 9+)
